# Саммари: свой Telegram-бот вместо LEADTEX

Дата: 2026-09-15  
Контекст: обсуждение в репозитории Prisma Meta (`prisma_meta`).  
Статус: **не реализовывать в этом репозитории.** Нужен **новый проект** и **новый агент**.

## Зачем это обсуждали

На площадке [LEADTEX](https://leadteh.ru/) (пользователь называла её leadtech) уже есть готовый Telegram-бот: там лежат контакты, по ним уже уходили рассылки. Вопрос: можно ли забрать этого бота «сюда» и слать рассылки самостоятельно.

## Что имелось в виду под «сюда»

Не сайт Prisma. Cursor — это среда разработки. Нужно:

1. **Разработать** бота в Cursor (сценарии, интеграции, рассылки).
2. **Выложить** на хостинг, где бот работает постоянно.
3. **Слать рассылки** с хостинга тем, кто уже нажал Start у этого бота.

Cursor сам не хранит подписчиков и не шлёт сообщения в Telegram. Он только пишет код. Отправка идёт с сервера.

## Ключевые решения

| Тема | Решение |
|---|---|
| Где жить коду | **Новый репозиторий**, не `prisma_meta` |
| Что такое Prisma | Публичный лендинг-навигатор. Без аккаунтов, CRM, бота и рассылок |
| Как связан сайт | Кнопки ведут в Telegram. Сейчас ТРИЗ-лендинг ведёт на `https://t.me/productodel_bot` — **кандидат** на перенос, нужно подтвердить |
| Тот же бот или новый | **Тот же Telegram-бот (тот же токен / тот же @username)**, иначе старая база не получит рассылку |
| Откуда контакты | Выгрузка из LEADTEX **до** отвязки токена. Telegram список подписчиков сам не отдаёт |
| Кто шлёт рассылку | Свой код на хостинге, не LEADTEX и не окно Cursor |
| Хостинг | Отдельный сервис (логичный кандидат — Railway, он уже есть у Prisma) |
| MVP | Сначала: приём Start, своя база контактов, импорт из LEADTEX, рассылка админом. Сценарии/оплаты/интеграции — следующим этапом |

## Как Telegram понимает «кто запустил бота»

1. Человек нажимает **Start** у конкретного бота.
2. Telegram присылает боту апдейт с числом `chat_id` (и `user_id`).
3. Площадка (LEADTEX или наш код) **записывает** этот id в свою базу. У Telegram нет кнопки «скачать всех, кто когда-либо нажал Start».
4. Рассылка — это цикл `sendMessage(chat_id, текст)` с токеном бота. Telegram пропускает сообщение, если этот человек стартовал **этого** бота и не заблокировал его.

Следствия:

- Один токен = один «владелец» (LEADTEX **или** наш сервер, не оба сразу).
- Новый бот = новая пустая база. Старым людям нужно снова нажать Start.
- Потеряли выгрузку из LEADTEX и отвязали токен — номера контактов не восстановить.

## Чего ещё нет (открытые вопросы для нового проекта)

- Подтвердить, что бот на LEADTEX — это `@productodel_bot`, а не другой.
- Есть ли доступ к токену в BotFather / LEADTEX → Каналы.
- Сколько контактов, какие поля в выгрузке (id, имя, username, теги).
- Кто админ рассылки (Telegram user id владельца).
- Нужна ли админка в браузере или достаточно команд в Telegram (`/broadcast`).
- Какой объём сценария с LEADTEX нужно повторить в фазе 2.
