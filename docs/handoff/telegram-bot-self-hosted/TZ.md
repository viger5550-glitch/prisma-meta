# ТЗ: свой Telegram-бот, база контактов и рассылки

Дата: 2026-09-15  
Продукт: отдельный Telegram-бот (не сайт Prisma Meta)  
Источник: обсуждение 2026-09-15 + саммари в [SUMMARY.md](./SUMMARY.md)

## 1. Цель

Сделать **свой** Telegram-бот, который:

- работает на нашем хостинге 24/7;
- сам копит контакты всех, кто нажал Start;
- принимает импорт контактов с LEADTEX;
- умеет слать рассылки **тем же ботом** людям, которые его уже запускали.

Сайт Prisma остаётся витриной и только ссылается на бота. Код бота **не добавлять** в репозиторий `prisma_meta`.

## 2. Зачем уходим с LEADTEX

Сейчас сценарии, контакты и рассылки живут в конструкторе LEADTEX (leadteh.ru). Нужно владеть этим контуром самим: разрабатывать в Cursor, деплоить на хостинг, запускать рассылки без кабинета LEADTEX.

## 3. Критерии успеха фазы 1 (MVP)

1. Человек открывает того же бота в Telegram, жмёт Start — запись появляется в нашей базе (`telegram_id` / `chat_id`, дата, username, имя, если есть).
2. Повторный Start того же человека не плодит дубликат.
3. CSV/Excel выгрузки из LEADTEX импортируется в ту же таблицу (по `telegram_id`).
4. Админ одной командой (или одним действием) отправляет текст сегменту «все активные». Сообщения уходят через Bot API.
5. Кто заблокировал бота — помечается, в следующие рассылки не попадает (или помечается после ошибки 403).
6. Бот крутится на хостинге по HTTPS webhook (не long polling на ноутбуке).
7. Секреты (токен, id админа) только в переменных окружения, не в git.

Критерий «рассылка из Cursor» **неверный**. Cursor пишет код. Кнопка «отправить» живёт у админа в Telegram (или в простой админке на том же хостинге).

## 4. Фаза 2 (не блокирует старт)

Делать **после** рабочего MVP, отдельным ТЗ:

- воронки и кнопки, которые сейчас в LEADTEX;
- оплаты;
- интеграции (Notion, CRM, таблицы);
- сегменты, теги, отложенные цепочки;
- аналитика открытий/кликов как в конструкторе.

В фазе 1 сценарий бота минимальный: `/start` → короткое приветствие; `/help`; админ-команды рассылки.

## 5. Как устроен Telegram (обязательная модель)

```
Пользователь --Start--> Telegram --update с chat_id--> наш сервер --INSERT--> база
Админ --/broadcast--> наш сервер --для каждого chat_id sendMessage--> Telegram --> пользователь
```

- Идентификатор для рассылки — целое число `chat_id` (для лички обычно равен `user.id`).
- Telegram **не отдаёт** полный список тех, кто когда-либо стартовал бота.
- Писать можно только тем, кто стартовал **этот** токен и не заблокировал бота.
- Спам по чужим id без Start технически не доставляется / запрещён правилами Telegram.

## 6. Миграция с LEADTEX (порядок нельзя менять)

1. В LEADTEX выгрузить контакты (архив / Excel). Обязательное поле: **Telegram ID**. Желательно: имя, username, телефон, теги, дата.
2. Сохранить файл в надёжном месте (не коммитить в git).
3. Развернуть нашего бота на хостинге **без** боевого токена или с тестовым ботом — проверить Start и рассылку на себе.
4. Импортировать выгрузку в базу (на стейдже — копия, на проде — боевые id).
5. В LEADTEX **отвязать** токен от канала Telegram.
6. Прописать тот же токен у нас, выставить webhook на наш URL.
7. Сразу проверить: `/start` от админа пишется в базу; тестовая рассылка 1–2 людям.
8. Только после этого считать LEADTEX необязательным. Старые воронки LEADTEX после отвязки токена **перестанут работать**.

Откат: токен можно вернуть в LEADTEX, но наша база и их база снова разъедутся. Пока токен у нас — рассылки только у нас.

## 7. Архитектура

Отдельный сервис. Рекомендуемый контур:

| Слой | Рекомендация | Зачем |
|---|---|---|
| Язык | TypeScript + Node 20+ | Совпадает со стеком Prisma, проще сопровождать |
| Telegram SDK | grammY или Telegraf | Webhook, команды, защита админа |
| HTTP | маленький сервер (Node `http` / Fastify / Express) | Telegram шлёт POST на `/webhook` |
| База | PostgreSQL (Railway) или SQLite на диске только для прототипа | Контакты и история рассылок |
| Хостинг | Railway (отдельный сервис от сайта Prisma) | Уже есть у экосистемы |
| Админ рассылки | команды в Telegram: `/broadcast`, подтверждение «да» | Без отдельного кабинета в MVP |
| Импорт | CLI или админ-команда с файлом, либо скрипт `npm run import -- file.csv` | Разовый перенос + доимпорт |

Альтернативы (Python + aiogram, другой хостинг) допустимы, если агент явно фиксирует выбор в README нового репо. Не тащить бота внутрь Next.js-приложения Prisma.

### 7.1 Данные (минимум)

Таблица `contacts`:

- `telegram_id` — BIGINT, PK
- `chat_id` — BIGINT (обычно = telegram_id)
- `username` — nullable
- `first_name` / `last_name` — nullable
- `source` — `start` | `leadtex_import`
- `status` — `active` | `blocked` | `deactivated`
- `started_at`, `updated_at`
- `tags` — текст/json, можно пусто в MVP

Таблица `broadcasts`:

- `id`, `created_at`, `created_by_telegram_id`, `text`, `status` (`draft` | `sending` | `done` | `cancelled`)

Таблица `broadcast_receipts`:

- `broadcast_id`, `telegram_id`, `status` (`sent` | `blocked` | `error`), `error_code`, `sent_at`

### 7.2 Лимиты Telegram

- Не палить `sendMessage` пачкой без паузы. Ориентир: ≤ ~25–30 сообщений в секунду в личку, лучше очередь с задержкой 30–50 мс и ретраем 429.
- Длинный текст: лимит 4096 символов на сообщение, иначе резать или слать несколько.
- Рассылка только админам из env `ADMIN_TELEGRAM_IDS` (список id через запятую).

### 7.3 Переменные окружения

```
TELEGRAM_BOT_TOKEN=
TELEGRAM_WEBHOOK_SECRET=   # secret_token webhook, если используем
PUBLIC_BASE_URL=           # https://....railway.app
ADMIN_TELEGRAM_IDS=        # 123,456
DATABASE_URL=
```

## 8. Поведение бота (фаза 1)

### Пользователь

- `/start` — сохранить/обновить контакт, ответить коротким приветствием (текст согласовать с владельцем; пока заглушка: «Бот работает. Подписка на сообщения включена.»).
- Любой другой текст — коротко «команды: /start». Не строить LLM-агента в MVP.
- Не просить телефон и email в MVP, если это не нужно для импорта.

### Админ (id из env)

- `/stats` — число active / blocked / всего.
- `/broadcast` — бот просит прислать текст следующим сообщением, показывает превью и число получателей, ждёт подтверждение `ДА`.
- `/broadcast_cancel` — сброс черновика.
- Опционально `/import` не делать через чат (файлы неудобны); импорт — скриптом.

Не-админ эти команды не видит / получает отказ.

## 9. Безопасность и правила

- Токен не логировать целиком.
- Webhook только с проверкой secret / ip Telegram по возможности.
- Не слать рассылку без явного подтверждения админа.
- Соблюдать правила Telegram против спама: только opted-in (Start), понятная отписка в перспективе. В MVP достаточно: кто заблокировал бота — отписался.
- Файл выгрузки LEADTEX — персональные данные, не класть в репозиторий.

## 10. Связь с Prisma Meta

Репозиторий сайта: лендинги, ссылка `https://t.me/productodel_bot` на `/triz`.

После переноса токена **ссылка на сайте не меняется**, если остаётся тот же @username. Менять Prisma не нужно, пока не сменится бот.

Не смешивать деплой сайта и бота в одном сервисе Railway.

## 11. Вне скоупа этого ТЗ

- Перенос визуальных воронок LEADTEX один-в-один.
- MiniApp.
- Рассылки из Cursor / из чата агента «по кнопке без хостинга».
- Email/SMS.
- Личный кабинет на prisma-сайте.
- Новый бот «с нуля» без миграции токена (ломает цель «старые контакты»).
